2026-09-14 11:29 agent-sandbox
fix(bootstrap): disable container IPv6 so squid stops dialing unreachable AAAA Anthropic's endpoints publish AAAA records, and squid resolves DNS itself instead of going through glibc, so it never sees AI_ADDRCONFIG filtering and happily dials those IPv6 addresses. The container has no IPv6 egress, so every such connect fails with ENETUNREACH; squid answers ERR_CONNECT_FAIL 101 / HTTP 503 and `claude` login dies at the platform.claude.com token exchange. Turn IPv6 off at the kernel on docker run. Squid then detects the non-functional stack at startup (BCP 177 warning), binds 0.0.0.0:3128 rather than [::]:3128, and stays on IPv4 for the life of the container. Containers created before this change must be recreated to pick up the flags.
